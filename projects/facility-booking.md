# 大学病院 施設予約システム(facility-booking)

> 最終更新: 2026-11-20

## 概要
| 項目 | 内容 |
|---|---|
| 種別 | 受託 |
| 顧客 | 大学病院(名称未確認) |
| 内容 | 院内の施設・設備の予約。すべての予約は管理者承認。料金計算・月次確定・試算書・レポート |
| 技術 | React 19 + Hono + PostgreSQL 18 + Caddy、ConoHa VPS |
| 規模 | 利用者 1,000 名 / 施設 500 件 / 設備 2,000 件 |
| **状況** | **見積の最終段階**(契約前) |
| **最終納品** | **2027年2月末** |

## 開発フェーズ(要件定義書 v2 §10)
| フェーズ | 内容 |
|---|---|
| Phase 1 | 基盤(DB・認証・権限)、マスタ、予約申請〜承認、ダブルブッキング防止、カレンダー、システム内通知 |
| Phase 2 | 繰り返し予約、料金計算、月次確定・試算書、レポート |
| Phase 3 | チェックイン、通知文面編集、前日リマインド、メンテナンスモード、CSV 一括登録 |
| Phase 4 | メール通知の有効化(SMTP 確定後)、2重化構成(要否確定後) |

- 打ち合わせ用の「機能一覧と工数」Excel では、実装済み・未実装を区分して工数(人日)を提示。未実装は**料金(月次確定・試算書)と、手順書・マニュアル(納品物)**に集中。

## 顧客の確認待ち(要件定義書 v2 §11、12 件)
重要なもの:
- メール送信の可否・調達先(通知の設計、Phase 4)
- **F-10「仮金額として5倍単価の料金で表示」の意味**(見積の作りが変わる)
- 現行の料金表・減免規定(Phase 2 に必要)
- 学科・施設・設備(100 件超)の一覧、施設管理者の任命体制(マスタ投入に必要)

## PM 観点の気づき
- **契約前に相当部分を実装済み**。見積が通らない・減額された場合の持ち出しリスクがある。見積額にはこれまでの実装分も含める前提か確認したい。
- 2027年2月は **宿泊税 SaaS の稼働(2/1)と重なる**。2月は両方の山が同時に来るため、facility-booking は 1 月中に機能を完成させ、2 月は受入・マニュアル・本番移行に充てる計画が望ましい。
- マスタ投入用データ(料金表・施設・設備一覧)の受領が遅れると後工程が詰まる → 受領期限を契約時に合意したい。
