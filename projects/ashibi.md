# ashibi(公共施設予約システム)

> 最終更新: 2026-11-20 / ユーザー提供情報 + リポジトリ調査

## 概要
| 項目 | 内容 |
|---|---|
| 種別 | 自社製品(**提案中**) |
| 内容 | 市民会館・体育館・運動場などの公共施設を、利用者がオンラインで検索・予約申請し、管理者が承認・却下。30分単位、料金は時間単価×利用時間 |
| 技術 | React 18 + Hono + PostgreSQL + Caddy(Docker)。団体ごとの表示設定(`tenants/`)、社内開発環境で複数団体を同時に起動可(`.env` の INSTANCE) |
| 開発 | 2026-10-15〜19 に初期開発、11-17 に団体別設定を追加 |

## 受注に向けて必要なこと(たたき台)
- [ ] **お試し(トライアル)の条件を決める**:期間(例:1〜2か月)、無償/有償、対象の施設・利用者の範囲、終了後の本契約の料金
- [ ] お試し環境の用意:団体ごとの本番相当の環境(URL・SSL・バックアップ)。現在は社内開発環境のみ
- [ ] 初期データ:施設・料金・休館日・管理者アカウントの登録(先方から一覧をもらう)
- [ ] 利用規約・プライバシーポリシー(一般の利用者が登録するため必須)
- [ ] お試し後の継続判断の基準と、振り返りの日程を最初に合意しておく
- [ ] 料金体系(月額/施設数/予約件数)と、2団体目以降へ広げるときの価格

## PM 観点の気づき
- **2団体とも好感触**なので、お試しの開始を早めるのが受注への近道。お試し環境の構築は ashibi の既存の仕組み(団体ごとの設定・INSTANCE)で対応できそう。
- 一般の利用者(県民)が使うため、個人情報の取り扱い・規約・問い合わせ窓口の準備が必要。
- **facility-booking(大学病院の施設予約)と機能が近い**(予約申請・承認・料金計算・カレンダー)。技術も同じ系統(React + Hono + PostgreSQL + Caddy)。facility-booking の方が機能は進んでいる(承認の取消・変更申請、試算書、見取り図など)。将来、共通部分を製品としてまとめると保守が楽になる。ただし facility-booking は受託なので、権利(著作権・再利用の可否)を契約で確認しておきたい。
- 公共施設の予約は自治体・外郭団体に横展開しやすい。2団体の導入実績が営業材料になる。
