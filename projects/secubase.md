# SecuBase(情報セキュリティ管理SaaS)

> 最終更新: 2026-11-20 / ユーザー提供情報 + リポジトリ調査

## 概要
| 項目 | 内容 |
|---|---|
| 種別 | 自社SaaS(**開発中**) |
| コンセプト | 情報セキュリティ管理を、ひとつの基盤に。Excel/Word を使わず、文書・台帳・計画・記録をブラウザで作成・承認・版管理・出力 |
| 対応規格 | Phase 1 は **iSSO** に必要な資料管理から。将来 SCS → ISMS を追加(同じ資料・証跡を複数規格へマッピング) |
| 技術 | React 19 + Mantine + Hono + Drizzle + PostgreSQL(RLS)、pnpm、認証は WorkOS(予定) |
| **稼働目標** | **2027年4月** |
| 自社の iSSO | iSSO コンサルに依頼中 |
| 開発 | 2026-10-04 開始、11-06 以降停止(Claude 102 コミット) |
| 事業資料 | `docs/business/`(戦略・意思決定・営業・マーケ・法務・サポート)あり |

## Phase 1 スコープ
文書のブラウザ編集、台帳、計画・評価・報告、様式・記録、承認ワークフロー、版管理、PDF 出力、エクスポート、添付、テナント分離、監査ログ

## PM 観点の気づき
- **自社SaaS が3つ並行**(宿泊税 SaaS・ryus-apps・SecuBase)。それぞれが独自にテナント分離・認証・課金・規約を持ち、**技術の選び方もばらばら**(ORM:Drizzle/Prisma、パッケージ管理:pnpm/npm、UI:Mantine/自前部品、認証:WorkOS/自前)。保守する人が少ないほど負担になるため、共通化の方針(どこまで揃えるか)を決めたい。
- 自社の iSSO 対応(isso-manager リポジトリ、コーポレートサイトの情報セキュリティ方針)と連動しているなら、**まず自社で使って実績を作る**のが販売上も有効。
- 2027年2月までは他案件が優先と思われる。再開時期の判断が必要。
